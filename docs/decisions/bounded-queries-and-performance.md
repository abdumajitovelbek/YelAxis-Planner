# Bounded queries and performance

**Status: implemented decision; measurements require a recorded environment.**

Bound visible results with stable keyset pages while preserving complete canonical totals, long
interval intersections and relevant constraints/recurrence. Query-plan tests assert owner-scoped
prepared statements and indexes. Dense interfaces use pagination and readable alternatives.

Performance fixtures exercise 1,000/10,000 Actions, multi-year blocks, dense timed/flexible days,
long prose/imported intervals, writes, reopen, offline startup and repeated full-document
navigation. Benchmarks retain exact durable counts and do not hide a failure by reducing the
workload.

Release budgets include 300 ms queries, 2,500 ms warm/reopen renders, 5,000 ms cold/full-check
renders, 1,500 ms acknowledged writes, 12,000 ms for eight queued writes, 100 ms heartbeat gaps and
a 1,536 MiB owned process-tree RSS ceiling. Chrome additionally measures backing/heap, retained
growth and long tasks. These are test thresholds for the recorded fixture/environment, not universal
user-device promises.

Capture physical viewport screenshots for performance evidence; huge full-document raster captures
measure additional screenshot/compositor allocations. Linux process profiling and browser-specific
heap APIs have separate coverage limits. Exact-image health reuse, bounded hashing, streaming
compression and buffer retirement preserve full validation and durable rollback semantics.
